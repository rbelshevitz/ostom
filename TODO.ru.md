# OSTOM — план разработки

Этот файл содержит только актуальную очередь. Исторические заметки и
завершённые чек-листы сохранены в [TODO.history.ru.md](TODO.history.ru.md).

## Текущие приоритеты

1. **Возобновляемая инвентаризация и manifest**
   - Потоково сохранять папки, письма, вложения и кандидатов восстановления.
   - Сделать append-only журнал источником истины для состояния, результата,
     размеров, контрольных сумм и ошибок.
   - Добавить проверки прерывания и продолжения на большом синтетическом
     источнике.

2. **Структурное восстановление вложений**
   - Потоково читать произвольные деревья XBLOCK/XXBLOCK/SLBLOCK, включая 4 КиБ.
   - Сохранять связь с письмом, заявленный/прочитанный/выгруженный объём,
     контрольную сумму и частичный или неудачный статус.
   - Проверить путь на настоящих OST/PST с вложениями.

3. **Доказательная база**
   - Зафиксировать ограниченную эталонную проверку здорового PST/OST.
   - Проверить дополнительные реальные OST и варианты сжатия/шифрования.
   - Явно фиксировать неподтверждённые случаи и не заявлять полное
     восстановление без доказательств.

4. **Готовность релиза**
   - Генерировать уведомления о зависимостях по фактическому графу Go и
     отдельно отмечать неоднозначные лицензии для проверки.
   - Запускать полный Go suite и большой acceptance smoke.
   - Проверять Windows-архив, контрольные суммы, release notes и состав только
     из runtime-файлов.

## Критерий готовности

Изменение воспроизводимо, возобновляемо и подтверждено тестами или corpus.
OSTOM не меняет источник, не скрывает частичный результат и не смешивает
indexed- и native-вывод.

## Граница scope

Генерация PST/OST остаётся внешним инструментом, а не частью Go runtime.
