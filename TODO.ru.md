# OSTOM — план разработки

OSTOM — локальный инструмент восстановления повреждённых Outlook-файлов
`.ost`/`.pst`, работающий только на чтение. Он сохраняет доказательства,
экспортирует всё, что удалось прочитать, не меняет исходный файл и не делает
выводов о полноте серверной копии.

### Текущая точка реализации

- Сборка native-сообщений ограничена одним сообщением и batch максимум из 64
  сообщений или 8 МиБ payload в памяти; большие вложения читаются из spool.
- Native-batch сначала записывается и проверяется, затем атомарно фиксируется;
  после commit ссылки на сообщения и вложения освобождаются.
- Indexed export хранит durable checkpoint `in_progress`/`exported`, чинит
  незавершённый output перед retry и пропускает только подтверждённые записи.
- stderr worker-процессов ограничен 64 КиБ; `Close()` collector освобождает
  сообщения, вложения, identity и временные spool-файлы.
- При совместном native recovery и indexed `go-pst` indexed-вывод изолирован в
  `Indexed/`, поэтому append-only mbox не дублирует native-результат.
- Добавлен явный режим `-native-only`: native recovery и durable manifest без
  запуска `go-pst`, watchdog и его побочных indexed-файлов.
- Остались доказательные проверки: настоящий OST/PST с вложениями, полный
  production-путь native attachment trees и cross-route dedup.
- Добавлен повторяемый smoke `scripts/smoke-external-ost.ps1`: по умолчанию он
  проверяет структурный native-путь, а минимумы узлов/сообщений/вложений можно
  задать отдельно для конкретного корпуса; freepst и GroupDocs больше не
  смешиваются в одном жёстком baseline.
- Добавлен probe `scripts/generate-attachment-pst.ps1`: pinned PST-Builder
  создаёт настоящий PST с вложениями. Вариант через EML-adapter уже даёт одно
  читаемое EML с большим вложением, но второе сообщение теряется, а indexed
  path сообщает об отсутствующем GUID property. Это частичный smoke
  совместимости reader-а, не полная поддержка PST; `go-pst` остаётся
  необязательным indexed backend, а не эталоном восстановления.
- Тот же генератор поддерживает `-NativeOnly` и проверяет отсутствие дерева
  `Indexed`; если созданный PST не даёт native-кандидатов, probe честно остаётся
  красным, а не маскирует несовместимость.
- Длинный generator smoke зелёный: 256 сообщений / 358 вложений / 51 large
  payload. Mbox smoke на 256 lazy-вложений также проверен; медленный запуск
  выявил побайтовую запись MIME-обёртки, теперь запись буферизуется. Тест
  проходит с исправленным окружением Go для процесса.
- Записи item-journal теперь сохраняют идентичность исходного файла, а итоговый
  manifest использует её вместо ошибочной подстановки route как source. Целевые
  тесты `cmd/ostom` и `internal/recovery/session` проходят.
- Точка остановки на сегодня: новые функции не добавлять. В следующем сеансе
  выполнить один полный `go test -trimpath ./...` с исправленными
  `GOROOT`/`GOPATH`, затем продолжить append-only inventory/manifest отдельно от
  новых функций восстановления.

## Большие файлы — возобновляемая обработка

Большие OST/PST нужно обрабатывать как возобновляемую задачу, а не как одну
неограниченную команду. Это задача командной утилиты и ядра, а не полировки
графического интерфейса.

Порядок реализации, чтобы пользователь не видел служебную мешанину папок:

- [ ] Хранить служебные данные только в скрытой папке `.ostom` внутри папки
  результата; в `Local Folders` не складывать ни журналы, ни незаконченные
  файлы.
- [x] Описать скрытую порцию работы отдельной записью с номером, состоянием,
  объёмом и контрольной суммой; считать её пригодной для продолжения только
  после проверки записи и результата.
- [x] Проверять не только один файл, но и целую папку результата порции:
  учитывать относительные имена, общий объём и содержимое всех файлов.
- [x] Для native-экспорта сначала писать порцию в скрытую папку, проверять и
  фиксировать её, а видимый результат собирать только после успешного прохода.
- [x] Возобновлять native-экспорт по подтверждённым порциям: привязывать их к
  сессии с отпечатком исходника, проверять перед использованием и повторять
  только отсутствующие или повреждённые порции.
- [x] Записывать MIME-сообщение и вложения потоково, не собирая целое письмо
  или кодированное вложение в ОЗУ; ограниченные данные в памяти оставлять
  только для уже найденных структурных кандидатов.
- [x] В CLI native-пути убрать накопление всех структурно найденных сообщений
  перед экспортом: выдавать кандидата обработчику сразу после разбора и
  освобождать тело после записи; старый списоковый интерфейс оставить для
  совместимости.
- [x] Ограничить промежуточную очередь native-экспорта небольшими порциями:
  не более 64 сообщений или примерно 8 МиБ данных, не считая одно текущее
  сообщение.
- [ ] Разделить временные и возобновляемые данные: системную `Temp` оставлять
  только для короткоживущих мелких файлов, а большие тела, порции и журнал
  хранить в скрытой рабочей папке OSTOM на том же диске, что и результат.
- [x] Перенести временное хранилище тел вложений из безымянной системной
  `Temp` в рабочую папку сессии; при нехватке места завершать текущую порцию
  понятно и сохранять уже подтверждённые порции.
- [x] Делить работу на самостоятельные порции и для каждой порции сначала
  писать временный результат во внутреннее хранилище.
- [x] После проверки порции помечать её завершённой; незавершённую порцию при
  следующем запуске удалять и выполнять заново.
- [x] Собирать видимый mbox только из завершённых порций во временный файл,
  затем одним безопасным перемещением заменять прежний результат.
- [x] При повторном запуске автоматически продолжать ту же задачу по скрытому
  состоянию; отдельные команды и служебные параметры пользователю не нужны.

До появления этих гарантий не включать пропуск писем только по записи журнала:
сам журнал не доказывает, что видимый результат не был удалён, изменён или
оборван.

- [x] Определить служебное состояние обработки: отпечаток исходника (размер,

- [ ] Сделать каждую порцию самостоятельной: временный результат, проверка,

- [ ] Возобновлять работу только при совпадении отпечатка источника и важных

- [ ] Добавить надёжное устранение повторов для результатов обычного и

## Текущая база

- Безопасная диагностика заголовка и индексов Unicode-файлов, включая вариант
  со страницами 4 KiB.
- Ограниченный обход NBT/BBT и HN/PC/TC. На реальном OST с вложениями он даёт
  13 кандидатов сообщений из 14 узлов сообщений и связанных сообщений;
  четыре вложения связаны с письмами и восстановлены; каждое сопровождается
  отдельным предупреждением о значении `PidTagAttachSize`.
- Кандидаты вложений сохраняют связь с родительским BID/NID, заявленный и
  фактически прочитанный размер, `Content-ID` и MIME-роль, если эти свойства
  доступны. Объём читаемых данных ограничен.
- Экспорт в Thunderbird `mbox + .sbd`, отдельный экспорт структурно
  восстановленных данных в `mbox` и `.eml`. Ошибка одного письма или вложения
  не останавливает весь экспорт.
- JSON-отчёт, контроль свободного места, ограничители времени и размера,
  а также сведения об источнике каждого кандидата.

## Готово означает

На копии настоящего OST OSTOM показывает папки/письма/вложения и их
читаемость, локализует ошибки, экспортирует каждый независимо читаемый объект
в Thunderbird-совместимую иерархию, создаёт воспроизводимую запись
восстановления и никогда не изменяет и не загружает исходник.
