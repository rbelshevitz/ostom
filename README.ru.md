[![Go](https://img.shields.io/badge/Go-1.24%2B-00ADD8?logo=go&logoColor=white)](https://go.dev/doc/install)
[![.NET](https://img.shields.io/badge/.NET-8.0-512BD4?logo=dotnet&logoColor=white)](https://dotnet.microsoft.com/download/dotnet/8.0)

> Помогает извлечь доступные письма и вложения из файлов Outlook OST/PST и перенести их в Thunderbird.

`ostom` — утилита для Windows, которая читает файлы данных Outlook и сохраняет найденные письма в формате, совместимом с Thunderbird. Программа открывает исходный файл только для чтения.

В первую очередь OSTOM помогает сохранить данные, которые могут находиться только на этом компьютере: письма из папок «Отправленные», «Черновики», «Исходящие», а также скрытых и пользовательских папок. Имя папки само по себе не показывает, есть ли её содержимое на сервере.

Основной сценарий — файлы данных классического Outlook для Windows, в том числе версии Outlook 2016, 2019, 2021, 2024 и Outlook для Microsoft 365. Это ориентир совместимости, а не обещание, что каждый файл будет прочитан полностью.

OSTOM не связан с Microsoft и не одобрен этой компанией. Названия Microsoft, Outlook, Windows и Microsoft 365 являются товарными знаками их владельцев.

## Быстрый запуск

Скачайте последнюю [версию для Windows x64](https://github.com/rbelshevitz/ostom/releases), закройте Outlook и сделайте копию OST/PST. Работайте с копией, сохранив исходный файл.

Проверить файл и создать отчёт:

```powershell
.\ostom.exe --output-dir E:\recovered source-copy.ost
```

Быстро проверить структуру без чтения писем и вложений:

```powershell
.\ostom.exe --check --output-dir E:\recovered source-copy.ost
```

Извлечь доступные письма для Thunderbird:

```powershell
.\ostom.exe --export-dir E:\recovered source-copy.ost
```

Дополнительно выполнить расширенное сканирование:

```powershell
.\ostom.exe --recovery-scan --export-dir E:\recovered source-copy.ost
```

После экспорта закройте Thunderbird и скопируйте созданную папку `Local Folders` в папку `Mail` профиля Thunderbird. Запустите Thunderbird и проверьте письма и вложения, прежде чем удалять исходные данные или резервную копию.

## Что умеет OSTOM

- Проверяет структуру файла и сообщает о найденных проблемах.
- Сохраняет читаемые письма и структуру папок.
- Продолжает обработку, если отдельное письмо или вложение прочитать не удалось.
- Создаёт дерево `Local Folders` для импорта в Thunderbird и отдельные файлы `.eml`.
- Сохраняет результаты расширенного сканирования отдельно от обычного экспорта. У таких находок могут отсутствовать часть сведений или исходный путь; некоторые могут повторять уже экспортированные письма.

Восстановить удаётся не всё. На одном общедоступном OST удалось экспортировать 12 писем и 4 вложения без ошибок. Это проверка одного файла, а не гарантия для всех разновидностей OST.

### Вложения

Для индексированных писем программа добавляет доступные вложения в письмо по мере чтения. При расширенном восстановлении вложение связывается с письмом только тогда, когда файл содержит явные признаки этой связи, а не просто совпадающее имя.

Статус `partial` означает, что удалось прочитать только часть данных; `unavailable` — что прочитать вложение не удалось. Сложные структуры вложений, повреждённые таблицы вложений и экспорт вложенных писем в отдельные файлы пока исследуются. Подробности и известные ограничения приведены в [FORMAT.ru.md](FORMAT.ru.md).

## Сборка и запуск из исходного кода

Для сборки нужен Go 1.24 или новее. Выполняйте команды из корня репозитория; при первой сборке Go загрузит необходимые зависимости.

```powershell
go build -trimpath -o ostom.exe ./cmd/ostom
go test -trimpath ./...
go vet ./...
```

Экспорт создаёт папку `Local Folders` с файлами почтовых ящиков. При `--eml` дополнительно создаётся папка `OSTOM EML` с отдельным `.eml` для каждого полностью прочитанного письма. Для встроенных в текст вложений сохраняется `Content-ID`, если он есть. Файлы индексов Thunderbird (`.msf`) не создаются.

Пустой файл почтового ящика не обязательно означает ошибку: он может соответствовать пустой папке исходного хранилища. Сводка и JSON-отчёт показывают, какие письма обработаны, экспортированы, сохранены частично или пропущены.

## Параметры командной строки

```text
ostom [--json] [--check] [--progress-json] [--eml] [--output-dir DIR] [--export-dir DIR] [--recovery-scan] [--quiet] file.ost
```

- `--json` — вывести машиночитаемый отчёт.
- `--check` — только быстрая структурная проверка; экспорт писем и вложений не запускается.
- `--progress-json` — писать события прогресса JSON-строками в stderr для GUI или автоматизации.
- `--eml` — дополнительно сохранять отдельный `.eml` для каждого индексированного письма. Без флага обычный экспорт пишет только mbox и экономит место.
- `--output-dir DIR` — сохранить JSON-отчёт в указанной папке. Если параметр не задан, при экспорте отчёт сохраняется в `--export-dir`.
- `--export-dir DIR` — создать экспорт для Thunderbird.
- `--recovery-scan` — выполнить дополнительное, более медленное сканирование. Требует `--export-dir`; найденные элементы сохраняются отдельно от индексированных писем.
- `--quiet` — не показывать сообщения о ходе работы. Предупреждения и итоговый отчёт остаются.

Событие прогресса содержит `done`, `total`, `total_known`, `unit` и `basis`. Это счётчик текущей фазы, а не притворно точный процент от размера PST/OST: при неизвестном общем числе `total_known=false`.

Для Windows 10/11 x64 проект также предоставляет `ostom-gui.exe` — компактный графический интерфейс к CLI восстановления `ostom.exe`. GUI выбирает PST/OST, каталог экспорта, запускает ядро отдельным процессом, показывает живой прогресс и итоговые данные по структуре, письмам, вложениям и перспективе восстановления. Пользовательская сборка публикуется как self-contained single-file приложение и не требует отдельно установленного .NET Desktop Runtime. `ostom-gui.exe` и соответствующий `ostom.exe` должны находиться в одной папке. Watchdog и частичный результат остаются видимыми, даже если отдельный файл проблемный.

GUI — это оболочка, а не второй движок восстановления: логика восстановления и экспорта остаётся в CLI, а GUI взаимодействует с ним через существующие аргументы и JSON/JSONL-прогресс.

Восстановление выполняется с ограничителями узлов, блоков, байт, записей и сообщений. Тяжёлые native- и indexed-проходы работают в отдельных worker-процессах с watchdog timeout; для больших файлов допустимое время native-прохода увеличивается, но ограничено сверху. Это защищает программу от зависания на повреждённом блоке, но не гарантирует полного чтения многогигабайтного файла.

Бинарные файлы релиза пока не подписаны. Windows SmartScreen может показать предупреждение при первом запуске. Перед запуском проверьте контрольную сумму архива по `SHA256SUMS.txt`, например:

```powershell
Get-FileHash .\ostom-v0.2.5-windows-amd64.zip -Algorithm SHA256
```

## Важно

Восстановление выполняется по принципу «что удалось прочитать». Успешное открытие файла или отчёта не доказывает, что в хранилище не осталось других писем и вложений. Всегда сохраняйте оригинал и проверяйте результат.

OSTOM читает исходное хранилище и не передаёт его содержимое куда-либо по сети. Отчёт и экспорт создаются в указанных вами папках. Вы отвечаете за сохранность исходного файла, проверку результата и соблюдение требований к конфиденциальности данных.
