# OSTOM

Безопасное извлечение читаемых писем из Outlook OST/PST.

OSTOM полезен, когда файл Outlook читается только частично и его нельзя
считать полностью исправным. Утилита переносит всё доступное в совместимое с
Thunderbird дерево mbox, показывает повреждённые участки в отчёте и не меняет
исходный файл.

OSTOM — это утилита только для чтения, извлечения и экспорта почты из файлов
Outlook. Это не ремонт и не перезапись PST: практическая ценность OSTOM — в
локальном спасении читаемых данных с честным результатом:

- обычный indexed-экспорт сохраняет доступные папки и письма;
- отдельный bounded native-путь может найти дополнительные письма при
  повреждённых индексах;
- письма и вложения записываются потоково, поэтому ошибка одного элемента не
  уничтожает остальной результат;
- отчёт и manifest различают экспортированные, частичные, неудачные и
  повторяющиеся находки.

## Быстрый старт

Работайте с копией файла и сохраняйте оригинал.

Проверить структуру и сохранить JSON-отчёт:

```powershell
.\ostom.exe --json --output-dir E:\recovered source-copy.ost
```

Экспортировать читаемые письма:

```powershell
.\ostom.exe --export-dir E:\recovered source-copy.ost
```

Принудительно выполнить отдельный recovery-проход:

```powershell
.\ostom.exe --recovery-scan --export-dir E:\recovered source-copy.ost
```

Закройте Thunderbird, скопируйте созданную папку `Local Folders` в его профиль
и проверьте письма и вложения перед дальнейшим использованием.

## Параметры

```text
ostom [--json] [--check|--analyze] [--progress-json] [--eml]
      [--output-dir DIR] [--export-dir DIR]
      [--recovery-scan] [--native-only] [--quiet] file.ost
```

- `--check` — быстрая проверка структуры без чтения содержимого писем.
- `--analyze` — ограниченный анализ содержимого без экспорта.
- `--export-dir DIR` — создать экспорт для Thunderbird.
- `--output-dir DIR` — сохранить `ostom-report.json` в указанной папке.
- `--recovery-scan` — принудительно запустить отдельный bounded recovery-путь.
- `--native-only` — пропустить необязательный indexed-путь `go-pst`.
- `--eml` — дополнительно сохранить `.eml` для восстановленных писем.
- `--json` — вывести итоговый отчёт в JSON.
- `--progress-json` — писать машиночитаемый прогресс в stderr.
- `--quiet` — скрыть текстовый прогресс.

`--recovery-scan` и `--native-only` требуют `--export-dir`. Indexed-путь
`go-pst` необязателен: его timeout или ошибка попадают в отчёт и не отменяют
отдельное ограниченное native-восстановление.

## Что ожидать

OSTOM показывает, что удалось прочитать именно из выбранного файла. Успешный
запуск не доказывает отсутствие нечитаемых данных. Native-находки могут не
иметь исходной папки или повторять indexed-письмо. Пустой mbox может означать
обычную пустую папку. Перед удалением источника или резервной копии проверьте
результат.

Windows GUI — тонкая оболочка над тем же CLI. Держите `ostom-gui.exe` и
соответствующий `ostom.exe` в одной папке. GUI рассчитан на системный
`.NET 8 Desktop Runtime`; если Windows сообщит об отсутствующем framework,
установите x64-версию `.NET 8 Desktop Runtime`.
