# OSTOM

[![CI](https://github.com/rbelshevitz/ostom/actions/workflows/ci.yml/badge.svg)](https://github.com/rbelshevitz/ostom/actions/workflows/ci.yml)
[![Go](https://img.shields.io/badge/Go-1.24%2B-00ADD8?logo=go&logoColor=white)](https://go.dev/doc/install)
[![.NET](https://img.shields.io/badge/.NET-8.0-512BD4?logo=dotnet&logoColor=white)](https://dotnet.microsoft.com/download/dotnet/8.0)

OSTOM — утилита для восстановления доступных писем из PST/OST-файлов Outlook
с экспортом в mbox и EML.
Она работает только на чтение и не изменяет исходный файл.

OSTOM полезен, когда файл Outlook читается только частично и его нельзя
считать полностью исправным. Он переносит доступные письма и вложения в
совместимое с Thunderbird дерево mbox, показывает повреждённые участки в
отчёте и оставляет исходный файл без изменений.

Это не ремонт и не перезапись PST. OSTOM нужен для локального спасения
читаемых данных с честным результатом:

Запись нового «вылеченного» PST/OST-файла в задачу OSTOM не входит. Утилита
не пытается собрать замену исходному файлу Outlook, а сохраняет найденные
письма и вложения в открытые форматы экспорта.

- обычный индексированный экспорт сохраняет доступные папки и письма;
- отдельный путь структурного восстановления может найти дополнительные
  письма при повреждённых индексах;
- письма и вложения записываются потоково, поэтому ошибка одного элемента не
  уничтожает остальной результат;
- отчёт и манифест различают экспортированные, частичные, неудачные и
  повторяющиеся находки.

## Быстрый старт

Работайте с копией файла и сохраняйте оригинал.

Проверить структуру и сохранить JSON-отчёт:

```powershell
.\ostom.exe -json -output-dir E:\recovered source-copy.ost
```

Экспортировать читаемые письма:

```powershell
.\ostom.exe -export-dir E:\recovered source-copy.ost
```

Принудительно выполнить отдельный восстановительный проход:

```powershell
.\ostom.exe -recovery-scan -export-dir E:\recovered source-copy.ost
```

Закройте Thunderbird, скопируйте созданную папку `Local Folders` в его профиль
и проверьте письма и вложения перед дальнейшим использованием.

## Параметры

```text
ostom [-json] [-check|-analyze] [-progress-json] [-eml]
      [-output-dir DIR] [-export-dir DIR]
      [-recovery-scan] [-native-only] [-quiet] file.ost
```

- `-check` — быстрая проверка структуры без чтения содержимого писем.
- `-analyze` — ограниченный анализ содержимого без экспорта.
- `-export-dir DIR` — создать экспорт для Thunderbird.
- `-output-dir DIR` — сохранить `ostom-report.json` в указанной папке.
- `-recovery-scan` — принудительно запустить отдельный ограниченный путь
  восстановления.
- `-native-only` — пропустить необязательный индексированный путь `go-pst`.
- `-eml` — дополнительно сохранить по одному `.eml` для восстановленных писем
  на выбранных путях экспорта.
- `-json` — вывести итоговый отчёт в JSON.
- `-progress-json` — писать машиночитаемый прогресс в stderr.
- `-quiet` — скрыть текстовый прогресс.

`-recovery-scan` и `-native-only` требуют `-export-dir`. Индексированный путь
`go-pst` необязателен: его тайм-аут или ошибка попадают в отчёт и не отменяют
отдельное ограниченное структурное восстановление.

## Что ожидать

OSTOM показывает, что удалось прочитать именно из выбранного файла. Успешный
запуск не доказывает отсутствие нечитаемых данных. Результаты структурного
восстановления могут не иметь исходной папки или повторять письмо из
индексированного экспорта. Пустой mbox может означать
обычную пустую папку. Перед удалением источника или резервной копии проверьте
результат.

Windows GUI — небольшой интерфейс для того же CLI. Держите `ostom-gui.exe` и
соответствующий `ostom.exe` в одной папке. Для работы требуется системная
среда выполнения `.NET 8 Desktop Runtime`. Если Windows сообщит, что нужная
среда не установлена, установите её x64-версию.

## Сборка и документация

### Дымовая проверка большого файла

Создать читаемый тестовый файл размером 2 ГБ с разреженным хвостом:

```powershell
.\tools\make-large-fixture.ps1
$env:OSTOM_LARGE_PST = (Join-Path (Get-Location) 'testdata\fixtures\large-2gb.pst')
go test -trimpath -run TestLargePSTRecoverySmoke ./cmd/ostom-fixture
```

Это проверяет работу с размером файла, адресное чтение, ограничения и ход
восстановления. Это не почтовый архив с 2 ГБ писем: исправная часть остаётся
маленьким исходным образцом, а хвост не содержит писем.

Чтобы проверить тот же запуск с ограничением памяти рантайма Go:

```powershell
$env:GOMEMLIMIT = '512MiB'
go test -trimpath -run TestLargePSTRecoverySmoke ./cmd/ostom-fixture
Remove-Item Env:GOMEMLIMIT
```

`GOMEMLIMIT` — мягкое ограничение рантайма, а не обещание, что весь процесс
Windows никогда не превысит этот объём. Дополнительно OSTOM ограничивает
объём полезных данных, блоков, узлов, писем и вложений; размер исходного файла
сам по себе не превращается в размер выделения памяти.

Сессия восстановления привязывается к точному содержимому исходника. Перед
продолжением OSTOM проверяет размер, время изменения, образец заголовка и
полный потоковый SHA-256. Полный хэш не требует большой памяти, но добавляет
один последовательный проход по очень большому файлу.

Требуется Go 1.24 или новее:

```powershell
go build -trimpath -o ostom.exe ./cmd/ostom
go test -trimpath ./...
```
